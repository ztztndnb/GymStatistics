# 食物 AI 营养分析报告设计

## 目标

将 AI 食物分析结果改为以原图为视觉背景的营养报告页，并让食物分析历史可稳定保留和展示该原图。分析结果仍不写入训练日期或日常饮食记录。

## 页面结构

分析完成后，先进入报告页，而不是直接进入逐项编辑表单。

1. 原始食物照片铺在页面顶部，作为报告的沉浸式背景。
2. 白色大圆角报告面板覆盖照片下部，可上拉和滚动。
3. 报告面板依次显示：
   - 食物名称、整份总重量与编辑入口；
   - 整份总热量主卡；
   - 碳水化合物、蛋白质、脂肪的三列整份合计卡；
   - 食材明细：名称、重量、每 100g 能量，并可进入编辑；
   - 三列营养信息网格，仅显示模型实际返回且有数值的营养项目；
   - 原有的分析说明或不确定性说明。
4. 页面滚动后，顶部收拢为仅含返回、总热量和食物名称的紧凑栏。
5. 底部操作栏固定：次操作为“编辑分析结果”，主操作为“保存到食物分析历史”。

不会加入餐次选择、分享、缩略图、彩色圆点、吐槽入口、减脂建议、体重管理建议或一键记录。

## 历史与图片存储

每条保存到食物分析历史的记录保存一个应用私有的图片副本。

- 保存时，将拍摄照片或相册图片读取后缩放，最长边不超过 2048px，使用 JPEG 保存。
- 图片放在应用私有目录 `food-analysis-images/`；记录保存相对文件名，不保存外部相册 URI 或绝对路径。
- 相册图片与相机图片采用同一保存流程，避免系统授权失效后无法显示历史图片。
- 仅在用户选择保存分析历史时创建持久图片；放弃、重拍或退出未保存分析时，临时图片仍按现有流程清理。
- 删除分析历史时，同时删除关联图片；图片缺失、旧记录或读取失败时，仍显示无图报告，营养数据与编辑功能可用。

## 交互与数据流

1. 相机或相册图片经确认后发送给模型。
2. 模型结果以报告页展示，并保留本次图片的临时来源。
3. 用户可进入现有编辑表单，逐项修改重量和每 100g 营养值；返回后继续查看同一报告页。
4. 保存时，将编辑后的记录和压缩图片副本写入食物分析历史。
5. 从历史列表打开记录时，默认进入报告页；通过底部编辑入口修改后，使用同一保存操作更新记录和图片。

## 兼容与错误处理

- 既有历史 JSON 数据没有图片字段时保持可读，使用无图报告布局。
- 图片写入失败时，不丢弃已分析的营养结果；界面提示图片无法保存，并允许用户决定是否仅保存文本分析记录。
- 图片解码失败时不阻塞报告、编辑或删除。

## 验证

- 单元测试覆盖：图片尺寸约束、历史记录关联文件名、删除时清理图片、旧记录兼容和缺图回退。
- 界面检查覆盖：报告页层级、仅展示已有营养项目、历史打开进入报告页、编辑与保存入口。
- 构建 debug 与正式版 APK；正式版命名为 `GymStatistics 1.3.9.apk`。
