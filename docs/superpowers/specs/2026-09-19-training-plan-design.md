# 训练计划设计方案

日期：2026-09-19  
状态：已确认，实施中  
范围：在现有手动训练记录基础上增加可重复使用的周训练计划和计划模式

## 1. 已确认的产品规则

- 训练计划采用一个可重复使用的周计划模板。
- 周期固定为周一至周日。
- 第一版只保留一个当前生效的训练计划。
- 计划动作保存完整预设数据：动作名称、重量、单位、次数、组数、备注和训练肌群。
- 计划动作必须通过明确的“完成并记录”操作才会生成真实训练记录。
- 完成后计划动作折叠，并在当天的实际训练记录中出现。
- 计划模式和现有手动模式共用同一套当天训练记录。
- 第一版不创建多个计划、不加入自动提醒和周期化加重。

## 2. 推荐方案与取舍

采用“计划数据整合进现有训练数据”的方案，而不是建立第二套独立训练数据库。

原因：

1. 计划和实际训练可以一起通过现有本地 JSON、局域网同步和导入导出流程保存。
2. 计划动作可以通过唯一 ID 与实际训练记录建立关联。
3. 旧版本的 `workouts.json` 可以依靠可选字段继续读取，不需要破坏已有训练数据。
4. 删除实际训练记录后，可以根据关联关系让对应计划动作重新变为待完成状态。

## 3. 数据模型

### 3.1 计划模板

在现有 `WorkoutData` 中增加一个可选的当前计划字段：

- `trainingPlan: TrainingPlan?`

`TrainingPlan` 包含：

- 计划名称，默认“我的训练计划”。
- 周一至周日的七个 `TrainingPlanDay`。

`TrainingPlanDay` 包含：

- 星期序号，统一使用 1 到 7 表示周一到周日。
- 是否为休息日。
- 当天有序的计划动作列表。

### 3.2 计划动作

每个 `PlannedExercise` 包含：

- 稳定且唯一的计划动作 ID。
- 动作名称。
- 预设重量、单位、次数和组数。
- 备注。
- 训练肌群。
- 排序位置由列表顺序表示，不额外保存可计算的序号。

从历史动作添加时，默认读取该动作最近一次完整记录作为预设值，用户可以在加入计划前修改。

### 3.3 实际记录关联

在现有 `ExerciseRecord` 中增加可选字段：

- `plannedExerciseId: String?`

手动添加的动作该字段为空；通过计划完成的动作写入对应计划动作 ID。该字段只表达来源关系，不改变现有动作名称、数据、备注和肌群的含义。

计划动作是否完成，不单独保存一份进度表，而是通过当前日期的 `SessionRecord.exercises` 查找对应的 `plannedExerciseId`。这样可以保证：

- 完成计划动作后自动生成实际记录。
- 删除实际记录后计划动作自动恢复为待完成。
- 历史日期的完成状态不会影响下一周同一计划模板。

## 4. 用户流程

### 4.1 进入计划管理

在主界面增加“训练计划”入口。进入后显示当前周计划编辑页，默认定位到本周。

计划编辑页支持：

- 切换周一至周日。
- 添加新动作。
- 从历史动作中选择动作。
- 修改预设数据和肌群。
- 调整当天动作顺序。
- 删除计划动作。
- 将某一天复制到另一日。
- 标记或取消休息日。

计划模板的修改立即影响尚未完成的计划展示，但不会修改已经生成的实际训练记录。

### 4.2 每日模式切换

在主界面当前日期训练区域放置一个滑动切换按钮，提供“手动模式 / 计划模式”两个选项。默认保持手动模式，避免更新后改变用户已有使用习惯。

两种模式共用当前选中日期：

- 手动模式：保留现有动作添加、编辑和删除流程；当天由计划模式完成并生成的动作，在动作卡片上增加“计划”标识。
- 计划模式：展示该日期对应星期的计划动作和完成状态。

“计划”标识只表示该条实际记录来自训练计划，不改变动作的编辑、删除、历史、搜索和趋势统计逻辑。手动添加的同名动作不自动显示该标识，除非用户在关联提示中确认将其关联到计划动作。

### 4.3 完成计划动作

计划模式中的每个动作显示：

- 动作名称。
- 预设重量、单位、次数和组数。
- 训练肌群。
- “完成并记录”按钮。

点击“完成并记录”后：

1. 使用计划数据创建新的 `ExerciseRecord`。
2. 生成新的实际记录 ID，并写入 `plannedExerciseId`。
3. 合并保存到当前日期的 `SessionRecord`。
4. 计划卡片折叠并显示已完成状态。
5. 手动模式下可以立即看到同一条实际训练记录。

如果当前计划动作已经完成，按钮不可重复创建记录。

### 4.4 手动模式联动

手动模式添加与计划同名的动作时，不直接猜测它对应哪一个计划动作，避免重复动作或同名动作造成误关联。

保存后可以提示“是否关联为计划动作”：

- 确认：为该实际记录补充 `plannedExerciseId`，计划动作变为已完成。
- 取消：保留为普通手动记录。

这项提示只在当天存在同名未完成计划动作时出现。

## 5. 与现有功能的联动

### 肌群和疲劳提醒

- 计划动作沿用现有肌群选择器。
- 完成计划动作前继续显示现有疲劳提醒。
- 疲劳提醒只提供警告，不阻止用户完成计划。
- 计划动作的实际记录进入现有历史、搜索和趋势统计。

### 编辑与删除

- 完成后的计划动作与普通训练记录使用同一编辑面板。
- 编辑实际记录不会修改计划模板。
- 删除实际记录后，对应计划动作恢复为未完成。
- 删除计划动作不会删除已经产生的历史训练记录。

### 数据同步和导入导出

- 计划模板与关联字段随现有 `WorkoutData` 一起保存和同步。
- 旧数据缺少计划字段时按“没有训练计划”处理。
- 导入数据时保留计划动作 ID，避免已完成状态丢失。
- 计划编辑不会改变现有训练日期和历史数据结构的含义。

## 6. 第一版不包含的功能

为控制范围，第一版暂不加入：

- 多套计划同时保存和切换。
- 增肌、减脂等计划模板市场。
- 自动通知、闹钟和后台提醒。
- 自动递增重量和周期化训练阶段。
- 计划动作自动顺延到下一天。
- 计划完成率以外的复杂统计。

## 7. 后续可扩展功能

第一版稳定后可以增加：

- 多套计划、计划暂停和归档。
- 训练周期与逐周加重。
- 动作替换和备用动作。
- 未完成动作的手动顺延。
- 每周完成率、连续训练天数和周报。
- 训练提醒和休息日提醒。

## 8. 实施边界

预计需要修改：

- 数据模型和 JSON 兼容字段。
- `WorkoutRepository` 或现有持久化入口。
- `GymViewModel` 的计划增删改、完成记录和关联逻辑。
- `GymApp` 的计划入口、周计划编辑页和每日模式切换。
- 现有测试脚本及新增计划逻辑单元测试。
- README 的用户功能说明。

不修改：

- 食物分析数据和相机功能。
- 现有疲劳提醒的“严格不足 3 天”判断规则。
- 现有日期页面的跟手滑动逻辑。
- debug APK 的名称规则。

## 9. 验收标准

1. 新安装或已有数据升级后都可以打开训练计划页面。
2. 可以创建周一至周日的计划，并为动作录入完整预设数据。
3. 可以从历史动作选择并编辑预设数据。
4. 计划模式只展示当前选中日期对应的计划动作。
5. 点击“完成并记录”只生成一条实际训练记录，重复点击不会重复添加。
6. 完成动作会折叠，并在手动模式的当天记录中可见。
7. 删除关联的实际记录后，计划动作会恢复未完成。
8. 计划动作参与现有肌群、疲劳提醒、历史、搜索和趋势功能。
9. 主界面的滑动切换按钮可以在手动模式和计划模式之间切换，并保持当前选中日期。
10. 手动模式中，计划模式生成的实际训练动作显示“计划”标识，普通手动动作不显示该标识。
11. 计划标识不影响动作编辑、删除、历史、搜索和趋势统计。
12. 旧版训练 JSON 可以正常读取，计划字段缺失时不崩溃。
13. 计划数据和计划关联字段可以随现有数据导出和导入。
